                                  ВВЕДЕНИЕ

   Лабораторный практикум предназначен для:

• получения необходимой информации по выполнению лабораторных работ;

• поиска источника информации с  программным  обеспечением  для  скачивания,
 установки и  настройки  всего  необходимого  для  выполнения  лабораторных
 работ;

• создания у студентов интереса к изучению курса «Интернет-технологии»;

• предоставления  необходимой  информации  по  условиям  сдачи  лабораторных
 работ, т.е. сроки сдачи, примерные объемы работ и отчетов;

• описания примерных алгоритмов выполнения лабораторных работ.

   В    лабораторном    практикуме    по     курсу     «Интернет-технологии»
продемонстрированы основные моменты выполнения лабораторных работ.

   Лабораторно-практические  занятия  проводятся   в   виде   индивидуальных
лабораторных  работ  и  предназначены  для  приобретения  каждым   студентом
индивидуальных  практических  навыков  по  разработке  web-технологий.  Темы
лабораторных работ и ожидаемые результаты по ним  представлены в табл. 1.

   Лабораторный практикум по курсу «Интернет-технологии»  содержит  основные
сведения, необходимые для выполнения  лабораторных  работ,  однако  в  таком
объеме нельзя  разместить  всю  необходимую  информацию,  поэтому  студентам
рекомендуется  самостоятельно  изучить  предложенную  литературу  и   другие
источники  по  этой  тематике.  В  подготовленном  лабораторном   практикуме
приведено описание инструментов, методов  и  алгоритмов,  владение  которыми
необходимо для выполнения лабораторных работ.

                           ЛАБОРАТОРНАЯ РАБОТА № 1

              ПРОЕКТИРОВАНИЕ И СОЗДАНИЕ СТАТИЧЕСКОГО WEB-САЙТА

Цель  работы  –  установка  инструментов  для   разработки   web-технологий,
проектирование, создание статического web-сайта с  набором  сервисов  и  его
раскрутка, изучение языка HTML.

Этапы выполнения работы

1. Разработать проект web-сайта для выбранной предметной области (прил. 1).
   Для создания сайта можно использовать предметную область,  выбранную  для
   создания БД по курсу «Базы данных». Пример структуры сайта представлен на
   рис. 1.
2. Произвести разметку web-страниц.
3. Установить  сайт  на  бесплатном  хостинге  или  на  отдельной  машине  с
   установленным web-сервером.
4. Организовать учет статистики посещений сайта.
5. Встроить баннеры поисковой системы, прогноз погоды, курсы валют и т.д.
6. Вставить метатеги с ключевыми словами на главную страницу сайта.
7. Включить свою страницу в базу  данных  одного  из  поисковых  серверов  –
   yandex,  rambler,  altavista.digital.com  и  др.  Позицию   сайта   можно
   определить с помощью приложения http://www.siteposition.ru/check.php. При
   помощи утилиты Site-Auditor (http://www.site-auditor.ru/index.html) можно
   собрать данные, необходимые для оценки видимости сайта в Рунете.
[pic]Рис. 1. Пример структуры сайта

8. Определить рейтинг сайта.
9. Разместить сайт на бесплатном  хостинге  (форма  заявки  для  одного  из
   бесплатных хостингов приведена
   в прил. 3.)
10. Создать средства поиска по сайту на основе ключевых слов.
11. Организовать коллекцию Линков по выбранной предметной области.
12. Включить на  созданный  сайт  дополнительные  сервисы  (прил.2).  Каждый
   студент реализует  минимум  пять  обязательных  сервисов  (список  сервис
   согласовывается с преподавателем).
13. Все сервисы должны работать самостоятельно, чтобы можно было  их  быстро
   объединить (сгенерировать) на любом сайте.
Общие требования

   Критерий проверки. Студент должен знать тэги языка HTML и их атрибуты. На
создаваемом web-сайте должны быть:

• текст разного цвета и размера;
• данные, представленные в соответствующей таблице;
• определены метаданные страницы;
• графические изображения,  сопутствующие  или  комментирующие  лабораторную
 работу;
• страницы, состоящие из более чем одного файла в формате HTML;
• ссылки внутри одного html-файла;
• страницы, доступные через Интернет и зарегистрированные хотя  бы  в  одной
 поисковой машине;
• протестированные с помощью  валидатора  http://validator.w3.org/  страницы
 сайта.

   При этом студент должен приобрести следующие знания и навыки:

•  общее  представление  о  браузерах,  назначении  пунктов  меню,   панелей
 инструментов и др.;
• владение навыками навигации в браузере;
• умение создавать, размечать web-страницы, подключать  графические  объекты
 на языке HTML.

   Отчетность. Функционирующий сайт на  бесплатном  хостинге  или  на  сайте
кафедры КССТ с обязательными сервисами (статистика посещаемости  сайта,  его
рейтинг, форум,  гостевая  книга,  поиск  по  страницам  сайта,  новости)  и
дополнительными сервисами из списка (прил. 2).

   Примечание: Выслать преподавателю по  электронной  почте  URL-адрес,  где
помещена лабораторная работа или показать на занятиях на ноутбуке.

   Объем отчетности. Сайт должен содержать не менее  10  web-страниц  (html-
файлов)  и  включать  в  себя  текст,  графику  (фото,  логотипы),  таблицы,
коллекцию ссылок на другие сайты. На главной странице должны быть  название,
содержание сайта, авторство, счетчик и др. Должно быть  реализовано  минимум
пять дополнительных оригинальных сервисов.

   Сроки представления – в течение первого месяца занятий.

                                                                Приложение 1

                    Инструкция по установке инструментов

   Что понадобится: Web-сервер Apache, язык  программирования  PHP,  система
управления базами данных (СУБД) MySQL.

   Установка и настройка Apache. Создайте на диске  C  директорию  с  именем
Server, в которой будет находиться сайт. Таким образом,  путь  к  локальному
серверу будет c:/server. Выберите директорию, куда можно установить  сервер,
название  группы  (оставьте  как  есть),  а  потом   сделайте   конфигурацию
установки (выберите  Typical).  Настройте  сервер.  Перейдите  в  директорию
Apache, затем в директорию conf внутри этой  директории  и  любым  текстовым
редактором откройте  файл  httpd.conf  на  редактирование.  Найдите  строчку
#Listen  12.34.56.78:80  и  замените  ее  на  Listen  127.0.0.1:80;   строку
#BindAddress  *  –  на  ’BindAddress  127.0.0.1’.   В   строку   ServerAdmin
you@your.address вместо you@your.address подставьте адрес своей  электронной
почты.  Строку  вида  #ServerName  new.host.name  замените   на   ServerName
127.0.0.1. В строке, начинающейся со  слов  DocumentRoot,  подставьте  адрес
ранее созданной серверной директории. После  этого  строка  будет  выглядеть
так DocumentRoot "c:/server". Небольшой абзац:

<Directory />

Options FollowSymLinks

AllowOverride None

</Directory>

 и его полностью заменяем на приблизительно такой:

<Directory "c:/server">

Options Indexes FollowSymLinks MultiViews +Includes

AllowOverride None

</Directory>

где c:/server – адрес  серверной  директории.  В  строчке,  начинающейся  на
’<Directory’,  подставьте  адрес  вашей  серверной   директории,   например,
’<Directory   "c:/server">’.   Строку   ’Options   Indexes    FollowSymLinks
MultiViews’  замените  на   ’Options   Indexes   FollowSymLinks   MultiViews
+Includes’. Перед строкой ’#AddHandler server-parsed .shtml’ уберите  значок
хэша. На этом первоначальная конфигурация web-сервера Apache  завершена,  он
настроен для исполнения SSI-директив.

   Установка и настройка PHP. Скачайте архив, распакуйте  его,  например,  в
директорию ’c:/php’(обратите внимание, что в архиве  может  быть  запакована
корневая  директория,  в  таком  случае  перепишите  в  ’c:/php’  содержимое
директории). Скопируйте файл  php4ts.dll  в  директорию  ’c:/windows/system’
(или туда, где находится подобная директория). После этого  вновь  поправьте
конфигурацию Apache httpd.conf. После строчки’# Dynamic Shared Object  (DSO)
Support’     вставьте      две      строки      ’LoadModule      php4_module
c:/php/sapi/php4apache.dll’ (если вы ставили PHP в  ’c:/php’)  и  ’AddModule
mod_php4.c’. В строке ’#AddType application/x-httpd-php .php’  убирите  хэш,
а следующей строкой добавьте  ’AddType  application/x-httpd-php  .php3’.  На
этом установка PHP и настройка Apache закончена.

   Установка MySQL. При установке СУБД MySQL серьезно  отнеситесь  к  выбору
логина и пароля для доступа к базе данных. Эти  логин  и  пароль  вы  будете
использовать для управления вашими данными. Адресом  хоста  вашей  локальной
базы будет ’localhost’. При переносе программного  обеспечения,  работающего
с MySQL на вашей локальной машине, в Интернет, не забудьте  изменить  данные
доступа на соответствующие вашему хостингу. Apache настраивать для работы  с
MySQL не требуется.

   Когда все поставлено и настроено, перезагрузите  машину.  Из  меню  Start
запустите Apache. Если все настроено, то появится и не  пропадет  консольное
окно с текстом вроде этого ’Apache/1.3.14 <Win32> PHP/4.1.3-dev  running...’
(если поставлен также и PHP). Если окошко тут же закрылось, то  имеет  место
ошибка конфигурации. Итак

   Когда все запустилось, пишите  простенький  html-код,  например,  «hello,
world», сохраните его в директории c:/server как  index.html  и  откройте  в
любом браузере. PHP-скрипты и страницы  можно  запускать  откуда  угодно  из
серверной директории. Выключите  Apache,  не  закрывая  консольное  окно,  а
выбирая соответствующий пункт из программной группы Apache. Если у  вас  все
настройки сервера в порядке, то можете пользоваться  небольшой,  но  удобной
утилитой Apache Manager для запуска, перезапуска и выключения сервера.

              Установка пакета «ДЕНВЕР» (http://www.drlab.ru )

   Про установку сервера и различных дополнений к  нему  написано  в  статье
«Apache + Perl + PHP4  +  MySQL  для  Windows:  руководство  по  установке»,
находящейся  по  адресу   http://www.dklab.ru/doc/apache/.   Инсталляцию   и
конфигурирование  компонентов  можно  произвести  автоматически  с   помощью
пакета «Денвер», который оптимизирован по объему, он занимает 2.1 Мб.  Пакет
«Денвер» и включает:

• Apache, SSI, mod_rewrite, mod_php;

• PHP4 с поддержкой GD и MySQL;

• MySQL с поддержкой транзакций (mysqld-max);

•  PhpMyAdmin-система  управления  MySQL  через   Web-интерфейс;   полностью
 заменяет командную строку MySQL;

• ядро Perl без стандартных библиотек (они поставляются отдельно);

• эмулятор sendmail (отладочная «заглушка», складывающая  приходящие  письма
 в /tmp); поддерживается работа совместно с PHP и Perl;

• система управления виртуальными хостами,  основанная  на  шаблонах.  Чтобы
 создать новый хост,  нужно  лишь  добавить  директорию  в  каталог  /home,
 править конфигурационные файлы не требуется;

• система управления запуском и завершением;

• инсталлятор (нечто вроде InstallShield).

                ОРГАНИЗАЦИЯ ОБМЕНА ДАННЫМИ МЕЖДУ ПРИЛОЖЕНИЯМИ

   Цель работы – получение навыков обмена данными между двумя приложениями.

   Этапы выполнения работы

▪ изучить протокол передачи новостных данных RSS;
▪ разработать структуру формата передачи  на  основе  XML  (для  новостей  в
 формате RSS);
▪  доработать  приложение  по  усвоению  выбранной  из   БД   информации   в
 структуре формата обмена;
▪ загрузить полученные  данные  в  другую  СУБД  или  произвести  прикладную
 обработку этого файла.

   Примером  обмена  данными  является  получение,   обработка   RSS-файлов,
манипулирование содержанием  этих  файлов  и  создание  на  их  основе  web-
страниц. Приложение скачивает RSS-файл, разделяет его на составные  части  –
элементы RSS, после чего вставляет части  этих  файлов  в  любом  порядке  в
подготовленные web-шаблоны, генерируя web–страницы на сайте.

   Схема выполнения третьей лабораторной работы представлена на рис. 2.

   Форма отчетности. Приложения, запускаемые с  web-сайта  (созданного  в  1
лабораторной  работе),  представляющие  данные  в  различных  форматах   для
использования  другими  приложениями  в  виде  ASCII  через  разделитель  со
списком полей; XML-файла и ASCII-файла, оконтуренного XML-тегами.

   Сроки представления – в течение четвертого месяца занятий.
